# 매일 자동 실행

Claude Code의 예약 작업으로 평일 아침에 브리핑을 자동 생성할 수 있습니다.

Claude에게 이렇게 말하면 됩니다.

```
평일 오전 7시에 아침 브리핑을 자동으로 만들어줘
```

아래는 그때 등록되는 프롬프트의 예시입니다. 예약 작업은 이 대화의 맥락을 기억하지 못하므로 프롬프트가 그 자체로 완결돼야 합니다. `{BRIEF_DIR}` 와 스킬 경로는 자기 환경에 맞게 바꾸세요.

## 주의

- 예약 작업은 **앱이 켜져 있을 때** 실행됩니다. 예정 시각에 닫혀 있으면 다음 실행 때 돌아갑니다.
- 그리고 **PC가 깨어 있어야 합니다.** 앱이 켜져 있어도 컴퓨터가 자고 있으면 실행되지 않습니다. 아래 절전 항목을 보세요.
- 첫 실행이 웹 검색 권한 프롬프트에서 멈출 수 있습니다. 사이드바에서 **Run now** 를 한 번 눌러 미리 승인해두면 이후로는 멈추지 않습니다.

## 절전이 발행을 막는다

이 스킬을 쓰면서 가장 오래 헤맨 문제입니다. 아침에 일어났는데 브리핑이 없고, 앱은 분명히 켜져 있었습니다.

원인은 윈도우 11의 최신 대기 모드(S0 Modern Standby)였습니다. 화면만 꺼진 것처럼 보이지만 실제로는 백그라운드 앱이 정지됩니다. 예약 작업이 예정 시각에 세션을 띄우기는 하는데 그 직후 전원 이벤트로 중단됩니다. 그래서 **아무 파일도 만들어지지 않은 채 조용히 실패합니다.**

### 진단

로그를 보면 확인됩니다.

```
%APPDATA%\Claude\logs\main.log
```

`Spawning new session` 다음에 `[likely sleep: power_event]` 가 이어지고 그 뒤로 아무 기록이 없으면 절전에 걸린 것입니다.

**여기서 한 번 더 속기 쉽습니다.** 예약 작업 목록의 `lastRunAt` 은 실행이 **시작됐다**는 기록일 뿐 성공했다는 뜻이 아닙니다. 이 값만 보고 정상이라고 판단하면 원인을 계속 못 찾습니다. 성공 여부는 그날 파일이 실제로 생겼는지로 판단하세요.

### 지금 설정 확인

```
powercfg /query SCHEME_CURRENT SUB_SLEEP STANDBYIDLE
```

`현재 전원 설정 인덱스` 가 0이 아니면 그 초만큼 지나서 잠듭니다.

### 해제

전원이 연결된 상태에서 안 자게 합니다.

```
powercfg /change standby-timeout-ac 0
```

노트북이라면 배터리 상태까지 0으로 두면 들고 나갔을 때 배터리가 빨리 닳습니다. 배터리 쪽은 남겨두는 편이 낫습니다.

```
powercfg /change standby-timeout-dc 10
```

화면은 꺼져도 상관없습니다. 문제가 되는 것은 대기 모드뿐입니다.

```
powercfg /change monitor-timeout-ac 10
```

## 끝나지 않은 실행이 다음 실행을 막는다

절전을 고친 다음 날에도 브리핑이 안 나왔습니다. PC는 깨어 있었고 앱도 켜져 있었는데 아무 일도 없었습니다.

이번에는 로그에 이렇게 찍혀 있었습니다.

```
[CCDScheduledTasks] Skipping dispatch for morning-news-brief: per_task_limit (active=1, limit=1)
```

예약 작업은 **같은 작업을 동시에 하나만** 돌립니다. 그런데 실행될 때마다 세션이 하나 열리고, **그 세션이 살아 있는 동안은 계속 실행 중으로 잡힙니다.** 전날 절전으로 중단됐다가 살아남은 세션이 슬롯을 놓지 않고 있었고, 그래서 다음 날 아침 스케줄러가 새 실행을 띄우려다 거부했습니다. 그 뒤로 1분마다 재시도하며 **699번 연속으로 건너뛰었습니다.**

절전과 증상이 똑같아 보이지만 원인이 다릅니다. 구별법은 간단합니다.

| 로그에 보이는 것 | 원인 |
|---|---|
| `Spawning new session` 뒤에 `[likely sleep: power_event]` | 절전에 걸려 중단됨 |
| `Skipping dispatch ... per_task_limit (active=1, limit=1)` | 이전 세션이 슬롯을 물고 있음 |
| 아무 기록도 없음 | 그 시각에 앱이 꺼져 있었음 |

### 푸는 법

세션 목록에서 그 작업 이름의 세션을 찾아 닫거나 보관 처리하면 됩니다. 슬롯이 풀리는 즉시 스케줄러가 놓친 실행을 따라잡아 실행합니다.

### 매일 이렇게 되지 않으려면

**세션이 저절로 사라지지 않는다는 것을 관찰로 확인했습니다.** 실행이 끝나고 21시간이 지나도 `실행 중` 상태로 남아 있었습니다. 그래서 작업 지시문 마지막에 이 단계를 넣었습니다.

```
N. 보고까지 끝냈으면 이 대화를 스스로 정리한다.
   archive_session 도구에 session_id 로 문자열 "self" 를 넘긴다.
   이 도구는 확인을 요구할 수 있다. 확인 단계에서 멈추더라도 발행은 이미
   끝난 뒤이므로 지장이 없다. 안 될 것 같아도 일단 시도하라.
```

승인 프롬프트 없이 실행되게 하려면 `~/.claude/settings.json` 의 `permissions.allow` 에 `mcp__ccd_session_mgmt__archive_session` 을 넣으세요.

이게 통하지 않으면 **브리핑을 읽고 나서 그 세션을 직접 닫아야 합니다.** 열어둔 채로 두면 다음 날 아침이 그대로 막힙니다.

## 실행이 중간에 끊길 때

세 번째 유형입니다. 앞의 둘과 달리 이건 **일부만 성공합니다.**

브리핑 HTML은 만들어지고 발행까지 됐는데 아카이브(`.md`)와 메일 본문이 없는 상태로 세션이 멈춰 있을 수 있습니다. 겉으로는 성공처럼 보입니다. 아티팩트에 오늘 날짜가 떠 있으니까요.

그런데 **아카이브가 빠지면 다음 회차가 이어받을 것이 없습니다.** 지난 섹터 상태, 미확인 항목, 「지켜볼 것」 체크리스트가 전부 그 파일에 있습니다. 이 시리즈는 어제 판단을 오늘 검증하는 구조라, 하루가 비면 그 고리가 끊깁니다.

그래서 확인은 아티팩트가 아니라 **파일 세 개가 다 있는지**로 하는 편이 확실합니다.

```
dir "%BRIEF_DIR%\*2026-08-25*"
```

`brief-YYYY-MM-DD.html`, `brief-YYYY-MM-DD.md`, `mail-YYYY-MM-DD.txt` 세 개가 나와야 정상입니다. 빠진 것이 있으면 그 부분만 이어서 만들면 됩니다. 발행된 HTML에 내용이 다 있으므로 그것을 근거로 채울 수 있습니다.

**놓친 실행을 이미 따라잡은 뒤에는 스케줄러가 그날 다시 돌지 않습니다.** 자동으로 채워지길 기다려도 오지 않으니, 빠진 것은 직접 채워야 합니다.

작업이 정상인지 한 줄로 확인하려면 실행 기록이 아니라 로그를 보는 편이 확실합니다.

```
findstr /C:"Skipping dispatch" "%LOCALAPPDATA%\Claude\logs\main.log"
```

여기에 줄이 잔뜩 나오면 슬롯이 막혀 있는 것입니다.

## 프롬프트

전체 프롬프트는 `SKILL.md` 의 절차를 그대로 옮긴 것입니다. 핵심만 옮기면 이렇습니다.

````
오늘자 아침 뉴스 브리핑을 만들어라.

`morning-news` 스킬을 사용한다. 스킬은 {SKILL_DIR}/SKILL.md 에 있다.
먼저 SKILL.md 를 읽고 거기 적힌 절차를 그대로 따른다.

1. {BRIEF_DIR} 에서 가장 최근 brief-YYYY-MM-DD.md 를 읽는다. 프런트매터의
   sectors / bond_view / short_cases / unresolved / verify 와 "지켜볼 것"을 파악한다.
   지난 회차 미확인 항목은 이번에 반드시 확보를 시도한다.

2. references/sources.md 를 읽고 1급 매체 우선으로 네 개 분야를 수집한다.
   시세는 반드시 마감 기사에서 종가를 쓴다. 연도를 확인한다.

3. 분야당 3~4건. 판정 칩과 지표 행 4개를 단다.

4. 인사이트(연결고리 / 반대편 시각 / 지켜볼 것).

5. references/desk.md 를 읽고 검증(F)과 여섯 개의 시선(A~E, G)을 쓴다.
   - F가 가장 먼저. 수치와 사실을 표로 검증한다. 판정은 확인 / 부분 확인 / 미확인 / 정정.
     G가 가져온 과거 통계도 이 표에 넣는다. 미확인 항목은 누구도 근거로 쓸 수 없다.
   - A 금리(3·10·30년물), B 산업(8개 섹터), C 리스크(2건),
     D 가치(기업 하나), E 거시와 생활(팀장), G 통계(표본 수 필수).
   - E가 주재하는 회의를 4~6라운드. E는 쟁점을 "그래서 누구에게 언제 도착하는가"로 세우고
     정리도 독자가 읽을 문장으로 번역한다. 자기 틀에 안 들어가는 이야기는 그대로 남긴다.
   - 만장일치 공통분모 + 양보한 것 + 끝까지 갈린 것.

   재료가 없으면 억지로 채우지 마라. "휴장", "재료 없음", "확인 못 함"이라고 쓰고
   왜 비었는지 설명한다.

6. 발행은 두 단계다.
   6-1. assets/brief-template.html 구조를 유지한 채 채워 {BRIEF_DIR}/brief-YYYY-MM-DD.html 로 저장.
        내용만 담는다. <div class="wrap"> 바깥에 아무것도 추가하지 않는다. 이 파일은 발행하지 않는다.
   6-2. powershell -ExecutionPolicy Bypass -File "{SKILL_DIR}/scripts/build-latest.ps1" -BriefDir "{BRIEF_DIR}"
        생성된 brief-latest.html 을 Artifact 도구로 발행한다.
        url: {LATEST_ARTIFACT_URL}   ← 반드시 넣어라. 빠뜨리면 고정 주소가 깨진다.
        favicon: 🌅

7. {BRIEF_DIR}/brief-YYYY-MM-DD.md 를 만든다. YAML 프런트매터를 규격대로.
8. {BRIEF_DIR}/mail-YYYY-MM-DD.txt 를 만든다. 메일 발송은 하지 않는다.
9. 고정 주소 링크와 4줄 요약으로 보고한다.

문장 부호: 줄표(긴 대시)를 쓰지 않는다.
출력 언어는 한국어. 확인되지 않은 수치는 지어내지 않는다.
````

## 왜 url 을 반드시 넣어야 하나

예약 작업은 매번 **새 대화**에서 실행됩니다. Artifact 도구는 그 대화가 발행한 적 없는 아티팩트를 갱신하려면 `url` 이 필요합니다. 빠뜨리면 매일 새 주소가 생겨서 고정 주소를 즐겨찾기 해둔 의미가 사라집니다.
