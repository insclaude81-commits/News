# morning-news-skill

매일 아침 기사를 직접 수집해 요약하고, **사실을 하나씩 검증한 뒤 여섯 개의 관점으로 해석해 모두가 동의하는 지점까지 좁힌** 브리핑을 만드는 Claude Code 스킬입니다.

헤드라인 목록이 목적이 아닙니다. 그건 포털에서 30초면 봅니다. 이 스킬이 만드는 것은 **여러 기사를 다 읽은 사람만 할 수 있는 말**입니다. 서로 다른 분야의 두 사건이 사실은 같은 원인을 공유한다는 관찰, 숫자 하나가 왜 통념과 어긋나는지, 오늘의 지배적 서사가 놓치고 있는 것.

## 결과물

하루에 세 개의 파일이 나오고, **고정 주소 하나**가 갱신됩니다.

| 파일 | 용도 |
|---|---|
| `brief-YYYY-MM-DD.html` | 그날의 내용. 발행하지 않고 아카이브 겸 빌드 재료로 씁니다 |
| `brief-latest.html` | 날짜별 파일을 합친 페이지. **매일 같은 주소로 발행**됩니다 |
| `brief-YYYY-MM-DD.md` | 기계가 읽는 아카이브. YAML 프런트매터에 그날의 섹터 상태·금리 뷰·검증 결과 |
| `mail-YYYY-MM-DD.txt` | 그대로 복사해 메일로 보낼 수 있는 본문 |

`brief-latest.html` 은 **주소가 바뀌지 않습니다.** 휴대폰에 즐겨찾기 하나만 두면 매일 아침 그 링크가 그날 내용으로 갱신되고, 상단 날짜 칩을 눌러 지난 회차를 볼 수 있습니다. 기본 14일치를 담습니다.

`examples/` 에 실제 산출물이 들어 있습니다. `sample-latest.html` 을 브라우저로 열면 날짜 전환과 검색이 그대로 동작합니다.

## 브리핑 구성

1. **지표 테이프** 그날의 핵심 숫자 5~7개
2. **4개 분야** AI·테크 / 경제·시장 / 국내 / 해외·국제 정세. 분야마다 판정 칩과 지표 4개, 기사 3~4건
3. **인사이트** 연결고리 2~3개, 반대편 시각 1개, 날짜가 박힌 지켜볼 것
4. **검증과 여섯 개의 시선** 아래 참고

## 검증과 여섯 개의 시선

같은 기사를 직업이 다른 여섯 사람이 읽으면 어떻게 갈리는지, 그럼에도 여섯이 모두 부정하지 못하는 지점이 무엇인지를 씁니다. 그리고 그 시선들이 딛고 선 사실이 맞는지 먼저 확인하는 사람이 하나 더 있습니다.

| | 관점 | 매일 다루는 것 |
|---|---|---|
| **F** | 검증 | 브리핑에 실린 수치와 사실을 하나씩 표로 확인. **토론 불참** |
| **A** | 금리 | 3년물 · 10년물 · 30년물 + 커브 |
| **B** | 산업 | 로봇 / AI 인프라 / 반도체 / 2차전지 / 자동차 / 조선 / 방산 / 에너지 |
| **C** | 리스크 | 그날 가장 취약한 두 곳. 무엇이 어떻게 깨지는가 |
| **D** | 가치 | 기업의 현금과 해자와 가격. 거시를 예측하지 않고 혼자 몇 년을 본다 |
| **E** | 거시와 생활 | 글로벌 변수가 한국 가계로 오는 경로와 시차. **팀장** |
| **G** | 통계 | 오늘과 닮은 과거 국면의 빈도. **표본 수를 반드시 밝힌다** |

**F가 가장 먼저 일합니다.** F가 "미확인"으로 판정한 항목은 A~E와 G 중 누구도 근거로 쓸 수 없습니다. G가 끌어오는 과거 통계에도 똑같이 적용됩니다.

그다음 E가 회의를 주재합니다. 채권 데스크가 사회를 보면 모든 논쟁이 "이게 어느 만기에 앉는가"로 수렴하는데, E는 **"그래서 이게 누구에게 언제 도착하는가"**로 쟁점을 세우고 합의를 독자가 읽을 문장으로 번역해 정리합니다. 다만 자기 틀에 안 들어가는 이야기는 억지로 끼워 맞추지 않고 그대로 남깁니다.

회의록에는 합의만 남지 않습니다. **누가 무엇을 양보했는지**, 그리고 **끝까지 갈린 지점과 그것이 언제 무엇으로 판별되는지**가 함께 기록됩니다. 여섯 전문가가 합의하지 못했다는 사실 자체가 정보이기 때문입니다.

A부터 G까지 모두 실존 인물이 아니라 관점의 유형입니다. 특정 투자자나 방송인을 흉내 낸 것이 아니라 분석 방식을 빌려온 것입니다.

## 설계 원칙

**모든 시각에 무효 조건을 붙입니다.** "지켜봐야 한다"는 무효 조건이 아닙니다. "10년물이 4.2% 아래로 내려가면"이 무효 조건입니다. 틀렸다고 인정할 사건을 미리 적어두는 것이, 이 브리핑과 아무 말 대잔치를 가르는 유일한 장치입니다.

**출처를 등급으로 나눕니다.** 블룸버그 · 로이터 · AP · 워싱턴포스트 · 매일경제 · 한국경제 · 연합뉴스 같은 1급에서 먼저 찾고, 못 찾을 때만 트래픽 상위 인터넷 매체로 내려갑니다. 개인 블로그나 자동 요약 애그리게이터는 쓰지 않습니다. 페이월 기사는 스니펫으로 사실을 확인하고 본문은 접근 가능한 매체에서 읽되, 출처에 `블룸버그 (한국경제 인용)` 처럼 둘 다 적습니다.

**시세는 종가만 씁니다.** 장중에 쓰인 기사에는 그 시점의 값이 실립니다. 실제로 이 스킬은 첫 회차에서 장중 -0.23%를 종가로 착각해 "코스피가 하락했다"고 쓸 뻔했습니다. 실제 종가는 +0.88%였습니다. 그 경험이 규칙이 됐고, 그래서 F가 생겼습니다.

**없으면 없다고 씁니다.** 주말과 휴장일에는 쓸 것이 없습니다. 그런 날 억지로 채우면 브리핑 전체의 신뢰가 깎입니다. 섹션을 비우고 왜 비었는지 한 줄로 설명합니다. 재료 없이 섹터 상태를 뒤집는 것은 분석이 아니라 소음입니다.

**어제와 이어집니다.** 매일 아침 어제 `.md` 를 읽어 후속 전개를 반영하고, 섹터 상태가 뒤집히면 그 사실을 표시합니다. 지난 회차의 오류를 발견하면 머리말에 정정 블록을 넣습니다. 브리핑은 어제 것을 근거로 오늘을 쓰기 때문에, 정정하지 않은 오류는 계속 굴러갑니다.

## 설치

```bash
git clone https://github.com/insclaude81-commits/News.git
```

Claude Code 개인 스킬 폴더로 복사합니다.

```
Windows  %USERPROFILE%\.claude\skills\morning-news\
macOS    ~/.claude/skills/morning-news/
```

그다음 `SKILL.md` 에서 두 곳을 자기 값으로 바꿉니다.

| 플레이스홀더 | 넣을 값 |
|---|---|
| `{BRIEF_DIR}` | 브리핑을 쌓을 폴더 경로 |
| `{SKILL_DIR}` | 스킬 설치 경로 |
| `{LATEST_ARTIFACT_URL}` | 첫 발행 후 받은 고정 주소 |

`{LATEST_ARTIFACT_URL}` 은 처음 한 번 발행해 보고 나온 주소를 적으면 됩니다. 이 값이 없으면 매일 새 아티팩트가 생겨 고정 주소의 의미가 사라집니다.

## 사용

Claude Code에서 이렇게 말하면 실행됩니다.

```
아침 브리핑 만들어줘
```

특정 분야만 요청해도 됩니다. `AI 뉴스만 정리해줘` 처럼 범위를 좁히면 기사 수를 늘리고 검증과 여섯 시선은 그대로 유지합니다.

### 매일 자동 실행

Claude Code의 예약 작업으로 평일 아침에 자동 실행할 수 있습니다. 프롬프트 예시는 [`docs/scheduled-task.md`](docs/scheduled-task.md) 에 있습니다.

**앱을 켜두는 것만으로는 부족합니다.** PC가 절전에 들어가면 예약 작업이 조용히 실패합니다. 같은 문서의 「절전이 발행을 막는다」를 먼저 읽고 전원 설정을 확인하세요.

## 폰에서 쓰기

발행된 아티팩트는 휴대폰 브라우저에서 그대로 열립니다.

- **날짜 칩** 상단에서 지난 회차로 전환. 주소 뒤에 `#2026-08-22` 를 붙이면 그 날짜로 바로 열립니다
- **검색** 기사 · 인사이트 · 섹터 · 검증표 · 회의 발언까지 실시간 필터링, 일치 부분 형광 표시. 지금 보고 있는 날짜 안에서만 찾습니다
- **헤드라인 모드** 기사를 제목만 남겨 한 화면에 넣고, 탭하면 그 기사만 펼침
- **섹터 타일 접기** 좁은 화면에서 8개 섹터를 이름과 상태만 보여주고 탭하면 논거 표시
- 읽기 진행률, 맨 위로

전부 클래스 이름만 보고 동작해서, 내용이 매일 바뀌어도 그대로 작동합니다.

## 구조

```
SKILL.md                    수집 · 요약 · 인사이트 · 검증 · 여섯 시선 절차
references/
  sources.md                출처 등급표, 분야별 검색어, 금리 데이터 소스
  desk.md                   A~G 페르소나 정의와 회의 규칙
assets/
  brief-template.html       라이트/다크 대응 템플릿 (내용 전용)
scripts/
  build-latest.ps1          날짜별 파일을 합쳐 고정 주소 페이지 생성
examples/
  sample-brief.html         날짜별 파일 실물
  sample-latest.html        합쳐진 고정 주소 페이지 실물
  sample-archive.md         기계가 읽는 아카이브
  sample-mail.txt           메일 본문
docs/
  scheduled-task.md         매일 자동 실행 프롬프트
```

발행 흐름은 두 단계입니다.

```
brief-YYYY-MM-DD.html  작성 (발행 안 함)
        ↓
build-latest.ps1       최근 14일치 합치고 상단 바 부착
        ↓
brief-latest.html      고정 주소로 재발행
```

날짜별 파일은 내용만 담고, 검색바와 날짜 칩 같은 조작 UI는 빌드 스크립트가 붙입니다. 그래서 템플릿 디자인을 바꾸면 다음 실행 때 지난 날짜에도 자동으로 반영됩니다.

## 만들면서 배운 것

실제로 부딪힌 문제들이 규칙이 됐습니다.

- 장중 수치를 종가로 착각 → **마감 기사에서 종가만 쓴다.** 그리고 검증 담당(F)을 따로 뒀다
- 한국어 검색에 작년 같은 날짜 기사가 섞임 → **연도를 확인한다**
- 페르소나들이 비슷한 말을 하기 시작 → **결론이 갈리지 않으면 실패로 본다**
- 유가 상승의 수혜 섹터여야 할 2차전지가 자동차와 같이 떨어짐 → **둘을 같이 묶지 않는다**
- 주말에 도는 몇 달 전 정보가 새 소식처럼 보임 → **후속 보도로 뒤집혔는지 확인한다**
- 통계는 표본이 작을수록 그럴듯해 보임 → **G는 표본 수를 반드시 밝힌다**
- 앱은 켜져 있었는데 아침에 브리핑이 없음 → **PC 절전이 원인이었다.** 대기 모드를 꺼야 한다
- 실행 기록(`lastRunAt`)을 보고 정상이라 판단 → **그 값은 시작만 기록한다.** 성공 여부는 파일이 생겼는지로 본다
- 절전을 고쳤는데 다음 날도 안 나옴 → **전날 세션이 안 닫혀 슬롯을 물고 있었다.** 작업 마지막에 스스로 정리하게 했다
- "내용만 담으라"는 지시를 따랐더니 CSS가 사라짐 → **제목·폰트·스타일은 wrap 바깥에 있다.** 무엇을 빼야 하는지 정확히 적는다
- 한 회차의 실수로 지난 회차까지 전부 깨짐 → **빌드가 최신 파일 하나에 전부를 걸지 않는다.** 없으면 이전 회차나 템플릿에서 가져오고, 결과에 색 토큰이 없으면 저장 자체를 멈춘다

## 면책

이 스킬이 만드는 브리핑은 뉴스에 대한 해석이며 투자 자문이 아닙니다. 등장하는 A부터 G까지는 실존 인물이 아닌 관점의 유형입니다. 요약과 해석은 원문을 재구성한 것이므로, 판단의 근거로 삼기 전에 원문을 확인하시기 바랍니다.
