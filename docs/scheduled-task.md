# 매일 자동 실행

Claude Code의 예약 작업으로 평일 아침에 브리핑을 자동 생성할 수 있습니다.

Claude에게 이렇게 말하면 됩니다.

```
평일 오전 7시에 아침 브리핑을 자동으로 만들어줘
```

아래는 그때 등록되는 프롬프트의 예시입니다. 예약 작업은 이 대화의 맥락을 기억하지 못하므로 프롬프트가 그 자체로 완결돼야 합니다. `{BRIEF_DIR}` 와 스킬 경로는 자기 환경에 맞게 바꾸세요.

## 주의

- 예약 작업은 **앱이 켜져 있을 때** 실행됩니다. 예정 시각에 닫혀 있으면 다음 실행 때 돌아갑니다.
- 첫 실행이 웹 검색 권한 프롬프트에서 멈출 수 있습니다. 사이드바에서 **Run now** 를 한 번 눌러 미리 승인해두면 이후로는 멈추지 않습니다.

## 프롬프트

````
오늘자 아침 뉴스 브리핑을 만들어라.

`morning-news` 스킬을 사용해서 진행한다. 스킬은 다음 경로에 있다:
<스킬 설치 경로>/SKILL.md

먼저 그 SKILL.md를 읽고, 거기 적힌 절차를 그대로 따른다. 요약하면:

1. 오늘 날짜를 확인하고, {BRIEF_DIR} 에서 가장 최근 brief-YYYY-MM-DD.md 파일을 읽는다.
   프런트매터의 sectors/bond_view/short_cases/unresolved 값과 "지켜볼 것" 체크리스트를 파악한다.
   후속 전개가 있으면 오늘 브리핑에 반영하고, 섹터 상태가 어제와 바뀌면 그 변화를 명시한다.

2. references/sources.md를 읽고 WebSearch·WebFetch로 네 개 분야(AI·테크 / 경제·시장 / 국내 /
   해외·국제 정세) 기사를 수집한다.
   - 1급 매체를 우선한다: 블룸버그, 로이터, AP, 워싱턴포스트, WSJ, FT, 니케이아시아, BBC /
     매일경제, 한국경제, 조선일보, 중앙일보, 동아일보, 연합뉴스, KBS·MBC·SBS.
     검색어에 매체명을 직접 넣어라.
   - 1급에서 못 찾을 때만 2급(트래픽 상위 인터넷 매체)으로 내려간다.
   - 개인 블로그, 브런치·티스토리, 자동 요약 애그리게이터, 브랜드평판·종목추천 같은
     홍보성 콘텐츠는 쓰지 않는다.
   - 페이월 매체는 스니펫으로 사실을 확인하고 본문은 접근 가능한 매체에서 읽되,
     출처는 `블룸버그 (한국경제 인용)`처럼 원출처와 읽은 매체를 함께 적는다.
   - 검색 스니펫만 보고 요약하지 말고 실제 본문을 읽어라. 시세는 반드시 마감 기사에서
     종가를 쓴다(검색어에 "마감", "종가", "closing"). 작년 기사가 섞이지 않았는지 연도를 확인한다.

3. 분야당 3~4건을 골라 요약하고, 각 기사에 "왜 중요한가" 한 문장을 붙인다.
   분야 머리에는 판정 칩(그 분야의 오늘을 한 마디로)과 지표 행(그 분야 숫자 4개,
   상단 테이프와 겹치지 않게)을 단다.

4. 인사이트 세 덩어리(연결고리 2~3개 / 반대편 시각 1개 / 지켜볼 것 3~4개)를 쓴다.

5. references/desk.md를 읽고 「세 개의 시선」을 쓴다. 이 섹션이 브리핑의 핵심이다.
   - A · 금리의 시선(팀장, 채권 20년차): 3년물·10년물·30년물을 매일 모두. 국채 금리를
     확인해 쓰고, 확인 실패 시 지어내지 말고 "확인 못 함"이라고 쓴다. 커브 도식 SVG의
     세 점 y좌표와 색을 그날 뷰에 맞게 조정하고 커브 관점을 쓴다.
   - B · 산업의 시선(섹터 애널리스트 20년차): 로봇 / AI 인프라 / 반도체 / 2차전지 /
     자동차 / 조선 / 방산 / 에너지 8개 섹터를 이 순서로 매일 모두. 각 타일에
     상태(긍정/중립/부정)와 오늘 기사에 연결된 2~3문장. 2차전지와 자동차는 유가에
     정반대로 반응하므로 같이 묶지 말 것. 2차전지는 셀 메이커와 소재사를 구분할 것.
     마지막에 관통하는 축 한 문단.
   - C · 리스크의 시선(역발상, 하방): 매일 정확히 2건. 논지 + 깨지는 지점 + 타이밍 리스크
     + 무효 조건. 어제와 같은 대상을 반복하지 말고, 어제 논지가 유효하면 한 줄로 갱신한 뒤
     새 건을 찾는다.
   - 그다음 A가 주재하는 데스크 회의를 3~5라운드 대화로 쓰고, 만장일치 공통분모 3~5개 항목
     + "양보한 것" + "끝까지 갈린 것"(및 그것을 무엇으로 판별할지)을 낸다.
   - 모든 시각에 무효 조건을 붙인다. 투자 권유가 아니라 해석으로 쓴다. A·B·C는 실존 인물이
     아닌 관점의 유형이며 실명이나 소속을 지어내지 않는다. 세 사람이 비슷한 말을 하면 실패다.

6. assets/brief-template.html 구조와 색상 CSS를 그대로 유지한 채 내용을 채워
   {BRIEF_DIR}/brief-YYYY-MM-DD.html 로 저장하고 Artifact 도구로 발행한다
   (favicon은 항상 🌅, title은 HTML 안 <title>에 "모닝 브리프 YYYY.MM.DD" 형식,
   description은 그날 한 줄 요약).
   - 헤드의 지표 테이프에는 그날 가장 중요한 숫자 5~7개를 넣고, 각 분야 첫 기사에는
     class="story lead"를 준다.
   - 템플릿의 「모바일 조작 레이어」 CSS와 문서 끝의 <script>는 절대 수정하거나 삭제하지 말 것.
     폰에서 쓰는 검색·헤드라인 모드·섹터 접기가 거기서 나온다. 거기서 매일 바꿀 것은
     상단 바 `.tb-badge` 안의 날짜(MM.DD) 하나뿐이다.
   - 검색이 걸리려면 마크업 클래스를 지켜야 한다: 기사 `.story`, 인사이트 `.item`,
     섹터 `.tile`, 만기 `.tenor`, 숏 케이스 `.short-case`, 회의 발언 `.turn`.

7. 같은 폴더에 brief-YYYY-MM-DD.md 를 만든다. 이 파일은 기계가 읽는 데이터다.
   SKILL.md의 "마크다운 아카이브" 절에 있는 YAML 프런트매터를 반드시 그대로 넣고,
   본문 제목 레벨도 규격대로 쓴다. 상태값은 정해진 어휘(긍정/중립/부정,
   상승압력/하락압력/중립)만 쓴다. 확인 못 한 수치는 null.

8. 같은 폴더에 mail-YYYY-MM-DD.txt 를 만든다. 형식은 SKILL.md의 "메일 본문 파일" 절에 있다.
   메일 발송은 하지 않고 파일까지만 만든다.

9. 마지막으로 아티팩트 링크와 파일 경로를 알려주고, 4줄(가장 큰 건 / 의외였던 것 /
   세 사람의 공통분모 / 오늘 안에 확인할 것)로 보고한다. 브리핑 전문을 다시 늘어놓지 말 것.
   어제 대비 섹터 상태가 뒤집힌 게 있으면 그것도 한 줄 덧붙인다.

문장 부호: 줄표(긴 대시)를 절대 쓰지 않는다. HTML, 마크다운, 메일 본문, 채팅 응답 전부
해당된다. 제목의 부연은 쉼표, 두 문장을 잇는 자리는 마침표, 라벨과 내용 사이는 콜론,
삽입구는 괄호를 쓴다. 가운뎃점은 제목이나 나열에서만 쓰고 종결어미 뒤에는 쓰지 않는다.

출력 언어는 한국어다. 확인되지 않은 수치나 사실은 지어내지 말고, 불확실한 부분은
불확실하다고 표시한다.
````
